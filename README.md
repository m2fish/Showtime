# Showtime Player 使用说明

会议音视频播放器 · **v1.8.1**（vMix 式双画面 + TAKE 按预览进度续播 + 图片直显 + 预览音频律动 + 四种播放模式 + 多播放列表 + 拖动排序 + 侧栏宽度可拖 + 播出中可切清单 + 4K HEVC 直连 + 绿色免安装打包） · Windows

---

## 1. 启动

### 1.1 绿色版（拿到文件夹直接用）

双击 `Showtime.exe` 即可。不需要安装 Node.js、Electron 或 ffmpeg，不需要管理员权限，也不写注册表。

- 播放列表与转码缓存存在同级 `data\` 目录，整个文件夹拷到别的电脑 / U 盘可直接迁移
- 首次运行 Windows 可能提示「未知发布者」，点「更多信息 → 仍要运行」（程序未做代码签名）
- 如果程序目录不可写（例如放在 `Program Files`），数据会自动回退到 `%APPDATA%\Showtime Player\`

### 1.2 源码运行（开发）

- 双击目录下的 `start.bat`，或在 `Showtime` 目录执行 `npm start`
- 首次运行需要 `npm install`（本目录已装好依赖）

程序依赖 `ffmpeg` / `ffprobe`：绿色版用内置的 `resources\ffmpeg\`；源码运行时按「环境变量 `FFMPEG_PATH` → 系统 PATH → `C:\ffmpeg\bin` → WinGet 安装目录」顺序查找。列表底部绿灯表示已就绪。

### 1.3 打包绿色版

```bash
npm run pack     # 输出到 桌面\ok\Showtime\
```

打包前把 `ffmpeg.exe` / `ffprobe.exe` 放进 `build/ffmpeg/`，脚本会一并打进 `resources\ffmpeg\`。

自带端到端自测：执行 `npm test`（需要 ffmpeg），自动生成测试媒体。除覆盖 v1.2.1 全部回归项（单击预览静止首帧、双击播出、TAKE、H.265 实时转码与缓存复用、转码会话复用、投屏真全屏与「只跟输出画面」、16:9 视口、控件作用域、窄屏不溢出）外，**v1.3 21 组**（TAKE 续播、图片导入 / 直显播出 / 投屏 / prepare、GIF 直显、四种播放模式、自动连播预览跟随、逐项停留时长、模式持久化与重启恢复；v1.6 已按图片直显语义更新）与 **v1.4 22 组**（多列表新建 / 切换 / 重命名 / 删除 / 折叠 / On Air 守卫 / 旧数据迁移 / v2 持久化、拖动排序与事件隔离 / 索引重映射 / 零中断 / Ctrl+↑↓ / 窄屏三列）全部带断言，加上 v1.7.2 播出中切清单 4 组，共 46 组。任一断言失败，`npm test` 返回非零退出码。界面截图输出在 `tools/` 下。v1.5 按用户要求未新增 `V15_*` 用例，律动与阴影改由手动验收（排障可看 `__showtime.vizState()`）。

> 打包版排障：用 `SHOWTIME_DEBUG=1` 启动，会把运行环境（是否打包、userData 与缓存路径、ffmpeg 命中路径）写到 `%TEMP%\showtime-diagnose.txt`。

## 2. 界面（v1.2 布局，v1.4 下排改三列）

```
┌──────────────────────── 标题栏 · 主题 / 窗口控制 ────────────────────────┐
│  PREVIEW · 预览（蓝，恒静音）      │  PROGRAM · 输出（琥珀，正式播出）       │
│  ┌────── 16:9 画面 ──────┐        │  ┌────── 16:9 画面 ──────┐          │
│  │ 播放 −5s 进度 时间 +5s 静音 │   │  │ 播放 −5s 进度 时间 +5s 音量 倍速 全屏 │ │
│  文件名 · 预览进度               │   │  文件名 · ON AIR · 播出时间           │
├────────────────────────────────────────────────────────────────────────┤
│  上一首 下一首 随机 [播放模式▾]   [ 切换 TAKE ]      显示器选择 / 投屏       │
├──────────┬───────────────────────────┬───────────────────────────────────┤
│ 列表侧栏  │ 播放列表（约 8 行可见）      │ 播放状态（400px 单列紧凑）          │
│ ＋ 新建   │ 单击预览 / 双击播出         │ 实时 / 投屏 / 转码 / 媒体信息        │
│ 切换 /折叠│ 拖动手柄调顺序 / 右键图片   │ 缓存占用                          │
└──────────┴───────────────────────────┴───────────────────────────────────┘
```

- **两个画面同时工作**：左侧预览给操作员核对，右侧输出是观众看到的画面，也是投屏的唯一画面源。
- 两个画面都按比例缩小为 16:9（1600×950 窗口下约 547×308），在各自半区内居中，四周为深色留白；画面底部各有一条**常驻播放控件条**。
- **画面内控件只管所在画面**：预览侧是播放/暂停、±5 秒、进度条、时间 + 静音标识；输出侧另加音量、倍速、全屏。拖动预览进度不会动到输出或扩展屏。
- 中间 44px 导播条只放全局操作：上一首 / 下一首、随机、**播放模式**按钮、TAKE、显示器选择、投屏。进度、音量、倍速等已下放到画面内。
- 列表里**蓝色描边 = 预览项**、**琥珀填充 = 播出项**，两者可同时指向不同文件；图片项显示「图片」标签、原图缩略图与停留时长。
- 下排最左是 **列表管理侧栏**（默认 168px，窄屏 148px，可折叠到 36px；**右侧分割线可拖动调节宽度 132–340px**）：多个播放列表按会议场次分开存放，点「＋ 新建」建新清单，单击切换、双击改名、右键或「⋯」删除。
- 每行左侧有 **12px 拖动手柄**（鼠标移到行上才显现），拖动即可调整议程顺序；正在播出的画面和扩展屏不会因调顺序中断。详见 3.2 节。
- 音频文件在两个画面窗显示封面卡；**预览的音频卡额外带一排跳动的律动条**（详见 3.3 节），输出音频卡与投屏窗口保持简洁。
- 下排状态面板为 400px 单列紧凑布局，投屏与转码区块固定在首屏，媒体信息往下滚动查看（字段一个不少）。
- 深色 / 浅色主题在右上角月亮 / 太阳按钮切换。窗口默认 1600×950，最小 1280×760。

## 3. 会议标准操作（重点）

1. 「添加文件」或把文件拖进窗口，用**行左侧拖动手柄**按议程顺序排好；不同场次可点左侧「＋ 新建」另建一份清单。程序会把第一项放到预览位（静止待命）。图片与音视频可以混排。
2. **单击**列表中的下一项 → 左侧预览**载入静止首帧，不会自己播放**；**观众画面完全不变**。
3. 需要核对片段时，点预览画面底部控件条的**播放键**（或按 `Shift + 空格`）才开始静音播放；也可直接**拖动预览进度条**定位到要开始播出的位置。这些操作不影响输出。
4. 确认无误后点「**切换 / TAKE**」按钮（或按 `T`）→ 该画面**从预览当前进度续播**到右侧输出并同步到扩展屏；预览未定位（进度 < 0.3 秒）时仍从 **00:00** 起播。鼠标悬停 TAKE 按钮可看到当前预览进度。
5. 切换后预览会**自动预载再下一项**，同样停在静止首帧，需要时手动点播放键核对。
6. 需要跳过预看直接播出时，**双击**列表项；此操作不改变左侧预览。
7. 输出画面的播放、进度、音量、倍速、全屏在**输出画面底部控件条**上操作，会实时同步到扩展屏。
8. 用导播条的**播放模式**按钮选择本场会议的行为（详见第 4 节）；正式会议若要求每段都人工确认，建议选「只播当前」。
9. 图片项按**停留时长**（默认 10 秒）播放，播完按当前播放模式推进或停止；在列表中**右键图片**可单独改该项的停留时长。

> 没有预览内容时 TAKE 按钮是禁用的。预览恒静音、不提供监听开关；未投屏时由输出画面出声，投屏时由投屏窗口出声。

### 3.1 四种播放模式

| 模式 | 播完当前项 | 到列表末尾 | 适用 |
|---|---|---|---|
| **顺序播放**（默认） | 自动进入下一项 | 停止，保留最后一帧 | 按议程连续播放 |
| **只播当前** | **停止，不自动切换** | — | 正式会议、每段都要人工 TAKE |
| 列表循环 | 自动进入下一项 | 回到第 1 项 | 展厅 / 暖场循环 |
| 单曲循环 | 重播本项 | — | 反复播放同一段 |

- 点导播条「播放模式」按钮打开菜单单选；按 `R` 依次循环四种模式，`Ctrl + M` 直接打开菜单。模式写入 `library.json`，重启后自动恢复。
- 「随机」开关只在「顺序播放 / 列表循环」下生效，另两种模式下点击会提示不生效。
- 手动「上一首 / 下一首」在任何模式下都可直接切换。
- 自动连播时状态面板会显示「自动连播 · 下一项 xxx」，预览同步预载再下一项的静止首帧（没有下下项时保留当前预览，不清空）。
- 「只播当前」与「顺序播放到末尾」结束时都**保留最后一帧**，主屏显示「播放结束」，投屏不突然黑屏。
- 状态面板实时区会显示当前模式；按起点续播时额外显示「起播点 +mm:ss · 按预览续播」。

### 3.2 多播放列表与拖动排序（v1.4）

**列表管理侧栏**（下排最左，168px；1280px 窄屏 148px；点「<」折叠到 36px 只留圆点，折叠后再点「>」或点一下窄栏顶部即可展开；右侧分割线可拖动改宽 132–340px，双击复位）：

| 操作 | 做法 |
|---|---|
| 新建 | 点「＋ 新建」→ 生成空的「列表 2 / 3…」并立即激活，名称可直接输入修改；旧列表内容原样保留 |
| 切换 | 单击列表条目；切换后两个画面恢复为该列表上次记录的预览 / 播出项，**暂停态、不自动播放** |
| 重命名 | 双击条目名称，或点条目右侧「⋯」→ 重命名；回车保存、ESC 取消 |
| 删除 | 「⋯」→ 删除列表，需二次确认；至少保留 1 个列表 |
| 导入范围 | 添加文件 / 文件夹 / 拖入文件一律进**当前激活列表**；同一个文件可以出现在不同列表里 |

- **播出中、投屏中都可以切换 / 新建列表**（v1.7.2 起）：观众画面不受影响，继续播原清单的内容。这时播放列表顶部会出现一条琥珀色提示条「播出中 · 观众画面来自〈某清单〉第 N 项」，点右侧「回到该列表」即可切回去（画面同样不中断）。
- **唯一被拦的是「删除正在播出的那个清单」**：会提示「该清单正在播出，请先停止播出再删除」，防止误删把观众画面正在用的内容一起带走。重命名、折叠、调宽侧栏始终不受限制。
- **调宽侧栏**：拖动「列表 / 播放列表」之间的分割线（鼠标移上去变亮），范围 132–340px，窗口不够宽时自动收窄以保证播放列表至少 420px；双击分割线或按 ← / → （Shift 加速）也可微调与复位。宽度随 `library.json` 保存，折叠后再展开仍是你调过的宽度。
- 多个列表共用同一份转码缓存，同一文件在不同列表里播放都直接秒开；列表数据保存在 `library.json`，旧版本只有一份清单的文件会自动迁移为「默认列表」，不会丢数据。

**调整曲目顺序**：

- 鼠标移到列表行上，左侧出现六点 **拖动手柄**；按住拖到目标行的**上半**插到它前面、**下半**插到它后面，蓝色指示线标出落点；靠近列表上下边缘会自动滚动，按 `Esc` 或拖出窗口取消。
- 也可选中预览项后按 `Ctrl + ↑` / `Ctrl + ↓` 移动（与 `Ctrl + ←/→` 切曲不冲突）。
- 重排**只改变顺序与高亮位置**：正在播出的 Program、播放进度、扩展屏画面全部不中断，不会重新加载或重新转码。
- 调顺序不影响单击预览、双击播出、右键改图片停留时长；外部文件拖进窗口仍走原来的导入流程，不会被当成排序。

### 3.3 预览音频律动（v1.5）

预览画面里的音频卡，在封面下方多了一排**上下对称跳动的律动条**（暗色主题紫青渐变、浅色主题蓝青渐变），用来一眼确认「这段音频真的在走」。

- **只有预览自己在播时才跳**：单击曲目只是载入（静止细线），点预览画面里的播放键或按 `Shift + 空格` 起播后开始跳动；暂停后约 0.6 秒收敛成一根细线，只剩轻微呼吸。
- **双击把音乐推到输出播出时，预览不会跳**——这是有意设计（v1.2.1 起预览一律不自动播放），需要核对时在预览里手动起播即可。
- 律动取的是**真实频谱**（预览元素自己的音频图）；需要 ffmpeg 转码的格式（wma / ape 等）拿不到频谱时，自动换成同样自然的程序化律动，不会卡住或报错。
- **仍然绝对静音**：静音由音频图末端的 0 增益保证，元素本身不再 `muted`，因此能拿到真实数据又不漏一点声音。
- 视频、图片、空列表时律动区自动隐藏；窗口最小化 / 暂停时停止重绘，空闲不占 CPU；系统开启「减少动态效果」时直接显示静止基线。
- 投屏窗口与输出画面**不会**出现律动，观众看到的仍是干净画面。

> 提一句观感变化：v1.5 把预览、输出两块画面下方的阴影减弱到原来的四成左右，浅色主题下边界更干净，与下排面板的直线接缝不再互相打架。

### 3.4 图片直显（v1.6）

图片不再转码成视频片段，**预览、输出、扩展屏三处都直接显示原图**：

- **点击即出画面**：单击预览、双击播出、TAKE、自动连播切换图片都是即时的，不再等待 2–9 秒转码（v1.5 时代 4K 图要等近 9 秒）。
- 停留时长、进度条、暂停 / 拖动、TAKE 从预览进度续播、四种播放模式全部照旧，由程序内置虚拟时钟计时。
- 换图前会**预解码**（双缓冲），输出与扩展屏上切换图片是无闪的硬切。
- **GIF 会动**：动图按原图直显正常播放动画。
- 改停留时长立即对画面上的那一项生效；旧的图片转码缓存（`still-*.mp4`）启动时自动清理。

| 按键 | 功能 |
|---|---|
| `T` | **TAKE 切换**：按预览当前进度续播到输出（未定位则 00:00） |

## 5. 格式兼容

程序自动判断，无需手工转换：

| 情况 | 行为 |
|---|---|
| mp4 / mov / webm + H.264/VP9，mp3 / flac / wav / m4a | 直接播放，秒开 |
| mkv / avi / ts 等容器，但内部是 H.264 | 实时转封装，1–3 秒出画面，几乎不占 CPU |
| H.265 / MPEG-2 / DTS / WMA 等不支持的编码 | ffmpeg 实时转 H.264 + AAC；4K 源降到 1080p 保证流畅 |
| **jpg / jpeg / png / webp / bmp / gif** | **v1.6 起原图直显：不转码，点击即出画面**，按停留时长计时播放 |
| **gif（动图）** | v1.6 起按原图直显，**动画会正常播放**（v1.5 及以前只取首帧） |

图片规格：原图直接上屏（Chromium 等比缩放、不裁切不拉伸，比例不符时左右或上下补黑边，与视频一致），不再转码成 1080p 片段，4K 大图也即刻显示且更清晰。默认停留 **10 秒**，右键列表项可单独设为 5 / 10 / 15 / 30 / 60 秒或自定义（1–3600 秒）；正在显示的该项改时长会立即生效（画面不变，只改计时）。`svg / tif / heic` 本期不支持，导入时忽略。

状态面板「转码 / 转封装」显示方式、百分比和速度。转码完成后写入缓存，下次播放同一文件直接秒开；**图片不再产生转码缓存**，旧的 `still-*.mp4` 会在启动时自动清理。图片的停留计时由程序内置虚拟时钟驱动，暂停 / 拖动进度 / TAKE 续播与视频行为一致。

**双画面共用转码**：预览与输出同时播放同一个需转码的文件时，只启动一个 ffmpeg 进程、共用一个流，不会重复转码或写坏缓存。按预览进度 TAKE 时，转码 / 转封装文件会从该点重新起转一个新片段，进度条与状态面板显示的是**全片绝对时间**（如 `01:23 / 05:00`），状态面板会标注「按预览 01:23 起转」。

> 缓存目录：`%APPDATA%\Showtime Player\cache`，上限 **10 GB**，超出按最久未用清理到 8 GB；14 天未访问也会清理。状态面板底部可查看占用并手动「清除缓存」。

## 6. 双屏投屏（会议用）

1. 先接好投影仪 / 扩展屏，在 Windows 显示设置里设为**扩展模式**（不是复制模式）。
2. 让**右侧输出画面**载入要播放的视频或图片（双击列表项或 TAKE）。
3. 点击导播条右侧「**投屏**」按钮（或按 `P`），旁边的下拉框可指定目标显示器。
4. 扩展屏立即**进入系统全屏**显示输出画面（无边框、无顶部亮线、覆盖任务栏）；主屏两个画面都保持静音预览，声音走系统默认输出设备。程序会先按目标显示器位置定位窗口，再进入全屏，并自动校验没有跑到主屏。
5. 播放、暂停、拖动、倍速、音量、切下一项都同步到扩展屏。
6. 按 `Esc` 或再次点击「投屏」结束。

注意事项：

- **扩展屏只跟 PROGRAM 输出**：单击列表预览、拖动预览进度、暂停预览、拖动调整列表顺序都不会改变观众画面或让投影闪黑。
- **投屏中切换清单不会中断投影**（v1.7.2 起）：扩展屏继续显示原清单的播出内容，播放列表顶部会标明观众画面来自哪个清单。唯一限制是不能删除正在播出的那个清单。
- 视频和图片都会投屏；**只有纯音频不投屏**，扩展屏保持纯黑待命。
- 待命页为整屏纯黑，无文字、LOGO 或控件；暂停或「只播当前」播完保留最后一帧。投屏窗口永远不叠加任何控件。
- 投影仪中途被拔掉，画面自动收回主窗口，播放不中断。
- 没有检测到扩展屏时点击投屏，会提示并改用本屏全屏。

## 7. 常见问题

**Q：上午 / 下午两场会议，能各存一份播放列表吗？**
可以。点下排最左「＋ 新建」建第二份清单，单击条目切换；每份清单各自记住曲目顺序、图片停留时长和上次的预览 / 播出项。导入文件只进当前清单，同一文件也能同时放进两份清单，缓存共用不重复转码。

**Q：列表项拖不动 / 找不到拖动手柄？**
手柄在每行最左 12px 处，鼠标移到行上才会显现（六点图标）；必须**按住手柄**拖，直接拖文字区域不会触发排序，以免和单击预览、双击播出冲突。也可以选中预览项后按 `Ctrl + ↑/↓` 移动。拖到目标行上半插前面、下半插后面，蓝色线标出落点，按 `Esc` 取消。

**Q：播出中切换了清单，观众画面会怎样？**
不会中断。v1.7.2 起 Program 有独立的「播出队列」：切清单只换左侧的操作视图，观众画面与投影继续播原来那个清单的内容，下一首也仍在原清单里推进。播放列表顶部会显示琥珀色提示条「播出中 · 观众画面来自〈某清单〉第 N 项」，点「回到该列表」可一键切回、演出不中断。状态面板的「播出队列」一行也会标出来源。

需要让观众画面换成新清单的内容时：在新清单里单击某项核对 → 点 TAKE（或双击直接播出）即可。

唯一被禁止的是删除正在播出的清单，会提示「该清单正在播出，请先停止播出再删除」。

**Q：点了列表项，观众画面没变，预览也没动？**
这是设计如此。单击只把内容载入左侧预览并**停在静止首帧，不会自动播放**；要看动起来的画面，点预览控件条的播放键或按 `Shift + 空格`。观众画面要点「切换 / TAKE」或按 `T` 才会播出；也可双击列表项直接播出。

**Q：TAKE 为什么还是从头开始播？**
v1.3 的 TAKE 按预览进度续播，而预览默认是静止首帧（进度 0）。请先在预览画面里手动播放一会儿，或直接拖动预览进度条到目标位置，再按 TAKE；悬停 TAKE 按钮可看到当前预览进度。进度小于 0.3 秒视为未定位，仍从 00:00 起播。

**Q：TAKE 后续播，转码文件会不会很慢？**
H.265 / MKV 等需要转码的文件会从预览进度处重新起转一个新片段，通常 1–3 秒出首帧；状态面板会显示「按预览 xx 起转」。新片段单独缓存，下次从同一起点播出可直接秒开。

**Q：怎么让每段播完都停下来等我确认？**
把播放模式切到「**只播当前**」（菜单或按 `R` 循环）。此时播完保留最后一帧、不自动切下一项，也不会让扩展屏回纯黑。

**Q：图片能播多久？能单独改某一张吗？**
默认 10 秒。在播放列表中**右键图片项**可选择 5 / 10 / 15 / 30 / 60 秒或自定义；设置随 `library.json` 保存，重启后仍有效。正在显示的那一张改时长会立即生效（画面不变，只改计时）。

**Q：投屏后顶部有一条线 / 没铺满？**
v1.2.1 起改为系统全屏，不再残留 Windows 窗口顶边。若仍看到细线，先确认 Windows 是**扩展模式**（复制模式下两块屏会显示同样内容），并把投影仪分辨率 / 缩放设为推荐值；也可在状态面板的投屏区块确认目标显示器。

**Q：拖动预览进度，输出会跟着动吗？**
不会。两个画面底部的控件条各自独立，预览控件只作用于预览总线；只有输出控件才同步到扩展屏。

**Q：预览为什么没有声音，控件条上也没有音量？**
预览恒静音，避免会议中误出声，所以预览控件条只放一个不可点击的「静音」标识。声音只来自输出画面 / 投屏窗口。

**Q：TAKE 之后预览怎么变成别的文件了？**
切换后预览会自动预载播放列表的下一项（同样停在静止首帧、不自动播放），方便连续会议，不影响当前播出内容。自动连播时预览也会跟着预载再下一项。

**Q：画面变小了，能看清吗？**
两个画面按 16:9 缩小到约 547×308（1600×950 窗口），用于核对内容足够；正式观看请看扩展屏输出，或按 `F` 让输出画面全屏。

**Q：状态面板信息不全？**
面板保持 400px 单列，字段一个未删；首屏固定显示实时状态、投屏与转码进度，媒体信息往下滚动查看。图片项会额外显示「停留时长」。

**Q：点播放没反应？**
看状态面板。若显示「转码失败」，通常是源文件损坏或编码过于冷门；若显示「ffmpeg 未就绪」，请检查环境变量。图片为原图直显，只有文件损坏或路径失效才会显示失败。

**Q：转码时拖动进度有延迟？**
拖动到尚未生成的位置时会等待该段转码完成再跳转。转码完成后拖动恢复即时响应，或下次播放直接走缓存。

**Q：双画面 + 投屏会不会很卡？**
最多三路同时解码。程序对同一文件复用转码会话，输出与投屏优先；预加载节流，主窗口最小化不影响投屏输出。图片为原图直显（换图前会预解码），解码压力很低。

**Q：声音要从会议室功放出来？**
程序固定使用 Windows 系统默认输出设备，请在系统声音设置里把默认设备切到功放即可，程序内不单独选择设备。

**Q：4K 视频转码很吃 CPU？**
4K 源会自动降到 1080p 转码；若原片就是 H.264 编码，则只做转封装，几乎不占 CPU。
